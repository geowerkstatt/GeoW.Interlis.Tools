Seite 2
p2-1
Zusammenfassung
p2-2
Dieser Standard beschreibt die Definition von Meta-Attributen als Teil eines INTERLIS-
Datenmodells. Mit den Regeln, die in der vorliegenden Spezifikation definiert werden, kön-
nen Meta-Informationen in ein INTERLIS-Datenmodell integriert werden, ohne dass dafür die
INTERLIS-Sprachspezifikation [1] angepasst werden muss.
p2-3
Die Syntaxregeln für Meta-Attribute werden in das Regelwerk von INTERLIS eingepasst.
Insbesondere wird definiert, an welchen Stellen in der bestehenden INTERLIS-Spezifikation
neu Meta-Attribute definiert werden können.

Seite 5

2 Einleitung

2.1 Überblick

s2.1-1
Meta-Attribute erlauben eine Ergänzung der INTERLIS-Modelle mit zusätzlichen Angaben,
die in der aktuellen Spezifikation von INTERLIS [1] nicht vorgesehen sind.
s2.1-2
Im Dokument zum INTERLIS 2-Metamodell [2] steht dazu:
s2.1-3
«Einem Metaelement können kompositorisch Metaattribute zugeordnet sein (Klasse "Me-
taAttribut"). Metaattribute sind weder durch die Sprache INTERLIS noch durch das Metamo-
dell genauer definiert. Sie dienen insbesondere dazu, dass Informationen, die über
INTERLIS hinausgehen, als Bestandteil der Modelldaten beigefügt werden können. Me-
taattribute haben einen Namen (Attribut "Name"), der innerhalb der Metaattribute desselben
Metaelementes eindeutig sein muss, und den beschreibenden Wert (Attribut "Value").»
s2.1-4
Im vorliegenden Dokument wird eine Syntax beschrieben, welche erlaubt, solche Meta-
Attribute direkt als Teil des Modells formulieren zu können. Dies im Gegensatz zum Meta-
modell, wo definiert wird, wie Meta-Attribute als Daten definiert bzw. in XML transferiert wer-
den.

2.2 Vorteile

s2.2-1
Die Definition von Meta-Attributen direkt im Datenmodell hat den Vorteil, dass Metainformati-
onen unmittelbar bei denjenigen INTERLIS-Konstrukten erfasst werden können, die sie be-
einflussen sollen. Die vorliegende Spezifikation ist so konzipiert, dass Meta-Attribute ohne
Änderung der INTERLIS-Spezifikation [1] angewendet werden können.
s2.2-2
Im Unterschied zu normalem Zeilenkommentar, der ausschliesslich informativen Charakter
hat, können Meta-Attribute gemäss den Syntaxregeln aus Abschnitt 4.2 von entsprechend
befähigten Softwarewerkzeugen interpretiert und ggf. für die weitere Verarbeitung weiterge-
geben werden.

3 Konzept

s3-1
Um die bestehende Sprachdefinition nicht ändern zu müssen, werden die Meta-Attribute in-
nerhalb von INTERLIS-Zeilenkommentaren formuliert. Ein INTERLIS-Zeilenkommentar ist
gemäss [1] wie folgt definiert:
s3-2
«Ein Zeilenkommentar wird mit zwei Ausrufezeichen eröffnet, die unmittelbar aufeinander
folgen. Der Zeilenkommentar wird durch das Zeilenende abgeschlossen.»
s3-3
Um Meta-Attribute von echtem Kommentar unterscheiden zu können, ist als drittes Zeichen
zwingend das Zeichen «@», einzufügen. Das heisst, ein Zeilenkommentar, der Meta-Attribute
enthält, beginnt mit «!!@».
s3-4
Zu welchem Meta-Element (gemäss INTERLIS 2-Metamodell) ein solches Meta-Attribut ge-
hört, ergibt sich aus der Position des Zeilenkommentars. Das Meta-Attribut bezieht sich auf
Seite 6
s3-5
das unmittelbar nachfolgende Sprachkonstrukt wie beispielsweise eine Modell-, Themen-
oder Klassendefinition.

4 Syntax

4.1 Syntax-Definitionen

s4.1-1
Die Syntaxregeln sind entsprechend der Extended Backus-Naur-Form (EBNF) definiert, wie
auch die übrigen INTERLIS-Sprachregeln (siehe [1], Abschnitt 2.1).
s4.1-2
Zusätzlich werden folgende Syntaxregeln eingeführt:
s4.1-3
~ A               Ein Zeichen aus allen möglichen Zeichen aber verschieden von den durch
s4.1-4
                  A definierten
s4.1-5
'A' .. 'D'        Ein Zeichen aus dem Bereich von Zeichen: «A», «B», «C» und «D»
s4.1-6
'\t'              Tabulatorzeichen                    Unicode: <CHARACTER TABULATION>
s4.1-7
'\f'              Seitenvorschubzeichen               Unicode: <FORM FEED (FF)>
s4.1-8
'\r'              Wagenrücklaufzeichen                Unicode: <CARRIAGE RETURN (CR)>
s4.1-9
'\n'              Zeilenvorschubzeichen               Unicode: <LINE FEED (LF)>

4.2 Syntaxregeln für Meta-Attribute

s4.2-1
Ein Meta-Attribut besteht aus dem einleitenden Code «!!@» sowie einem Meta-Attribut-
Namen und einem zugewiesenen Meta-Attribut-Wert:
s4.2-2
MetaAttribute = '!!@' Name '=' Value { ';' [ Name '=' Value ] } .
s4.2-3
Ein Meta-Attribut-Wert wird entweder aus einem Namen oder einem freien String gebildet:
s4.2-4
Value = Metaattributename | String .
s4.2-5
Ein Metaattributename ist eine beliebige Zeichenfolge (max. 255 Zeichen Länge) ohne be-
stimmte Sonderzeichen:
s4.2-6
Metaattributename = (* ~( '\t' | '\f' | '\r' | '\n' | ' ' | '='
s4.2-7
   | ';' | ',' | '"' | '\' ) *) .
s4.2-8
Ein String ist eine beliebige Zeichenfolge inklusive «Escape»-Sequenzen; eingeschlossen in
doppelte Anführungszeichen:
s4.2-9
String = '"' { Escape | ~( '"' | '\' ) } '"' .
Seite 7
s4.2-10
Eine Escape-Sequenz beginnt mit einem Backslash, gefolgt entweder von einem doppelten
Anführungszeichen oder einem Backslash oder einer vierstelligen Hex-Unicode-
Zeichennummer:
s4.2-11
Escape = '\' ( '"' | '\'
   | 'u' HexDigit HexDigit HexDigit HexDigit ) .
s4.2-12
Ein Unicode-Zeichen wird aus Hexadezimalzahlen gebildet. Diese bestehen aus Ziffern und
den Buchstaben a/A bis f/F:
s4.2-13
HexDigit = '0' .. '9' | 'a' .. 'f' | 'A' .. 'F' .

Seite 10
s5-37
Meta-Attribute zu einer Topic-Definition werden in den Schemadaten, das heisst, den Me-
taobjekten gemäss Metamodell [2] dem «SubModel» zugeordnet (und nicht der «DataUnit»).
s5-38
Meta-Attribute zu einer Konsistenzbedingungs-Definition («ConstraintDef») sind als Sche-
madaten nicht möglich, weil Constraints gemäss Metamodell [2] keine OID haben bezie-
hungsweise kein «MetaElement» sind.

6 Beispiel

s6-1
Folgendes Beispiel soll den Gebrauch von Meta-Attributen illustrieren. Dabei wird ange-
nommen, in einem INTERLIS-Datenmodell soll der verwendete Zeichensatz (ISO-8859-1)
angegeben werden. Gemäss Syntaxregel in Kapitel 4 besteht das entsprechende Meta-
Attribut aus folgenden Elementen:
s6-2
 Meta-Attribut-Element                                INTERLIS-Codefragment
 Zeilencode                                           !!@
s6-3
 Meta-Attribut-Name                                   ili.charset
s6-4
 Meta-Attribut-Wert                                   ISO-8859-1
s6-5
Ein vollständiges, gültiges Beispiel sieht also INTERLIS-Code wie folgt aus:
s6-6
 INTERLIS 2.3;
 !!@ ili.charset = ISO-8859-1
 MODEL Example AT "mailto:noreply@localhost" VERSION "2010-02-30" =
 END Example.
s6-7
Das Meta-Attribut würde einem Objekt der Klasse «Model» aus dem Metamodell mit dem
Namen «Example» zugeordnet:
s6-8
 <IlisMeta07.ModelData BID="MODEL.Example">
s6-9
    <IlisMeta07.ModelData.Model TID="Example">
      <Name>Example</Name>
      <iliVersion>2.3</iliVersion>
      <Contracted>false</Contracted>
      <Kind>NormalM</Kind>
      <At>mailto:noreply@localhost</At>
      <Version>2010-02-30</Version>
s6-10
    </IlisMeta07.ModelData.Model>
s6-11
    <IlisMeta07.ModelData.MetaAttribute
        TID="Example.METAOBJECT.ili.charset">
s6-12
      <Name>ili.charset</Name>
      <Value>ISO-8859-1</Value>
      <MetaElement REF="Example" />
    </IlisMeta07.ModelData.MetaAttribute>
s6-13
 </IlisMeta07.ModelData>
